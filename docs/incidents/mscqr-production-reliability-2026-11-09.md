## Shared dependency map

```text
Browser navigation → AuthContext → request coordinator → API client
  ├─ /auth/me and /auth/refresh → pre-auth and actor rate limits → token rotation
  ├─ TanStack queries → protected route → authenticate → session capability
  │    ├─ dashboard stats → RepeatableRead transaction → snapshot scope → snapshot data
  │    ├─ notifications → B03 authenticated transaction → notification function
  │    ├─ attention queue → B03 notification + attention + printing projections
  │    └─ batches → capability assertion → batch scope → rows → total → enrichment
  └─ managed EventSource → cookie-authenticated SSE → dashboard/printer streams
       → version events and query invalidation
```

Confirmed shared dependencies: session capability verification is used by dashboard, B03 and batch reads; dashboard and attention queue both use Prisma interactive transactions and returned P2028. Their internal bottlenecks are **not** proven to be identical. Refresh and SSE share browser authentication state, but the observed 401 and 429 have no proven common request initiator. Notifications' canonical denial is an independent response-classification defect fixed in source by #815.

## Authentication lifecycle and refresh 429

`src/contexts/AuthContext.tsx:174-233,281-340` restores with `/auth/me` and `/auth/refresh`, deduplicates a provider refresh, holds transient 429/503 states and observes Retry-After. `src/lib/api/internal-client-core.ts:379-414,421-440,534-617` deduplicates refresh per client, uses the browser lock across tabs, advances the session epoch on successful rotation, rejects stale-scope responses, and stores refresh cooldown by authenticated actor when available. Account settings and step-up recovery also call the provider `refresh`; protected-request 401 can call `refreshOnce`. These are the source initiators, not a measured per-browser count.

`backend/src/routes/modules/authRoutes.ts:129-140,303` applies pre-auth, route, IP and `account.security:actor` limiters before the refresh controller. The last limiter permits 12 requests per 15 minutes and resolves `req.user?.userId`. At this point no authentication middleware has populated `req.user`, so `backend/src/middleware/publicRateLimit.ts:67-75` falls back to the client IP for this *actor-named* bucket. Redis backs the limiter when configured. The 2026-11-09 19:51:51 CloudWatch event reported `scope=account.security:actor`, `authModel=anonymous`, `offenderKind=ip-ua`, `retryAfterSec=175`, followed by `/api/auth/refresh` 429; login had returned 200 immediately before. At 19:46:03 `/api/auth/me` returned 401. Four actor-scope limit events were visible between 19:46 and 19:54. The prior bounded investigation counted twelve refresh outcomes before the 429, without reliable browser/tab attribution.

**INCIDENT_ID:** REFRESH_429. **ENDPOINT:** `POST /api/auth/refresh`. **REQUEST_ID:** not reliably correlated to one browser in the supplied evidence. **EXPECTED:** ordinary authenticated navigation does not exhaust refresh security limits. **ACTUAL:** 429 with Retry-After during manufacturer use. **CONFIRMED_ROOT_CAUSE:** the configured actor limiter uses an IP fallback on the refresh route; this can group users behind one IP. Whether that grouping or unnecessary requests exhausted this specific production bucket is **UNVERIFIED**. **REQUIRED_FIX:** first capture a sanitized browser initiator timeline across tabs and server request IDs. If it proves redundant calls, correct the initiating path or reuse existing coordination. If it proves unrelated actors share a bucket, design a verified stable actor key without accepting untrusted identity or weakening abuse limits. **REGRESSION_TEST:** concurrent requests, same/different actors behind one IP, rotation, Retry-After, multi-tab, logout and revoked session. **SECURITY:** CSRF, rotation, revocation and rate limits remain enforced. **PRODUCTION_VERIFICATION:** normal navigation window with request count, 429 count, and no unexpected logout.

## SSE lifecycle and 401

`src/lib/api/internal-client-admin-ops.ts:165-188,298-314` opens dashboard and printer streams. `src/lib/api/managed-event-source.ts:65-111,140-203` shares a keyed native EventSource, sends cookies with `withCredentials`, closes on error, reconnects with bounded exponential backoff, pauses while hidden, and closes on logout. Dashboard mounts in `src/pages/Dashboard.tsx:139`; notifications mount in `src/features/layout/hooks.ts:184`. `backend/src/routes/modules/realtimeRoutes.ts:296-344` applies pre-auth limits, `authenticateSSE`, role/tenant gates and stream limits. `backend/src/middleware/auth.ts:242-259` prefers cookie access tokens for browser EventSource; it returns 401 for missing token or invalid/expired token. Query token compatibility is conditional and is not the intended production browser route.

**INCIDENT_ID:** SSE_401. **ENDPOINT:** `GET /api/events/dashboard`, `GET /api/manufacturer/printer-agent/events`. **REQUEST_ID:** Windows recorded `50abc662-25f4-406e-8db3-4ed53d1e4531` for dashboard and `d655df01-35b8-44e4-96bb-8d850be657af`, `20a3403e-3bd7-4358-a733-e1d99c9d1c2d`, `3d91de3a-5995-4bba-99c8-d56ab1ae88ba` for printer streams. **EXPECTED:** a valid session keeps one correctly scoped stream per endpoint and reconnects after renewal. **ACTUAL:** all four 401 responses said `Invalid or expired token`; later stream requests returned 200. A 19:57:32 refresh returned 200, both streams started at 19:57:33, and a printer-list read returned 200 at 19:57:36. These observations do not identify which validation step failed. The bounded backend correlation search found no `auth_session_capability_denied` record for the four SSE request IDs. **CONFIRMED_ROOT_CAUSE:** none. **REQUIRED_FIX:** distinguish signed-access-token validation from session-capability hydration, then correlate cookie-presence, EventSource initiator and refresh/rotation timing. Reproduce the identified transition before changing reconnection. **REGRESSION_TEST:** both streams through refresh, reconnect, hidden tab, tenant switch, logout and duplicate mount. **SECURITY:** never put credentials in URLs or bypass `authenticateSSE`. **PRODUCTION_VERIFICATION:** bounded valid-session navigation with both streams connected, no unexpected 401/reconnect storm.

## Batch latency

**INCIDENT_ID:** BATCH_LATENCY. **ENDPOINT:** `GET /api/qr/batches`. **REQUEST_ID:** Windows recorded `0f179a25-ba91-40ac-b9de-cd4e882832a8`, `7a877930-6561-4814-b22d-5e2ec85efbce`, and `187d6611-36ae-40b6-944a-a8cb3349d0e5`. **EXPECTED:** correct, responsive tenant-scoped inventory, pagination and totals. **ACTUAL:** the first and third successful responses took 11,612.7 and 12,623.6 ms in backend request telemetry; adjacent scoped-read proof events took 8,560.8 and 11,439.2 ms and returned two rows.

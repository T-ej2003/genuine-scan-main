# MSCQR Staging Cost Estimation Evidence

Date: 2026-07-02
Scope: private cost evidence for the first staging API Terraform plan.

This document defines the cost evidence path before any future staging apply. It
does not authorize `terraform apply`, AWS mutation, deployment, production
database use, production/global/table RLS enablement, runtime route wiring, or
committing private infrastructure identifiers.

## Purpose

Create a cost estimate after the first real staging Terraform plan and before
any apply approval. The estimate must be based on the generated plan, not
guesses or copied production assumptions.

## Allowed Estimation Inputs

Use one or more of these, depending on availability:

- Terraform plan summary generated by `npm run plan:staging-terraform`.
- Infracost, if available locally and approved for private plan input.
- AWS Pricing Calculator, entered manually from reviewed plan details.
- AWS Cost Explorer and AWS Budgets after resources exist.

Do not commit cost tool output if it contains private resource identifiers,
subnet IDs, VPC IDs, operator CIDRs, private ARNs, or raw plan details. Commit
only sanitized monthly estimate ranges when safe.

## Required Cost Categories

Estimate and review:

- ALB hourly cost and LCU usage.
- ECS Fargate CPU and memory hours.
- RDS instance, storage, and backups.
- Redis or Valkey node cost.
- NAT and data transfer, if used.
- CloudWatch logs ingestion and retention.
- KMS key monthly cost and request cost.
- S3 storage and request cost.

## Cost Guardrails

- Staging `desired_count` should stay `1` unless explicitly approved.
- RDS should stay on a small instance class unless capacity review approves a
  larger class.
- Redis or Valkey should stay on a small node class unless capacity review
  approves a larger class.
- Log retention must stay bounded.
- Multi-AZ must stay disabled unless explicitly approved.
- Broad NAT expansion must not be added unless required and reviewed.

## Private Evidence Folder

Use `.terraform-plans/staging/` for local-only evidence. It may contain:

- Terraform plan binary.
- Terraform plan text.
- Sanitized plan summary JSON.
- Private cost estimate notes.
- AWS identity guard output.
- Screenshot or export proving required GitHub checks are enabled.

The folder is gitignored and must stay local/private. If evidence is moved to an
external store, redact private values before sharing screenshots or excerpts.

## Apply Boundary

Cost evidence is required before any future apply approval, but it does not
authorize apply by itself. Apply still requires a separate approval step,
reviewed plan evidence, reviewed identity, rollback notes, and owner approval.

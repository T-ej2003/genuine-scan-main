# Phase 3 prepublication predecessor recovery

Release Train may encounter an authenticated registration and IAM policy successor while the reviewed broker alias still runs the older task map. The ordinary prerequisite reader correctly rejects that split. Supply both `prepublication_predecessor_source_sha` and `prepublication_predecessor_ticket_id` only when the historical coordinator has completed registration and policy results for that exact source and ticket.

The hosted coordinator verifies source ancestry, the historical START, both immutable result artifacts and their original signed authorizations. Historical authorization is checked at the authenticated completion time; it does not permit another write. The coordinator records the selected transaction IDs once under the new release identity. The existing receipt-bound registration predecessor validator then authenticates native receipts, Terraform/ECS/IAM state, the unchanged reviewed alias and the exact newer policy task map before preparing any new registration. A fresh authorization remains mandatory for each new mutation. A missing or conflicting old result, changed input, unverified signature or live drift stops the release. If a registration preparation or adoption already exists without the exact pinned predecessor, a later request for that predecessor stops; use a newly authorized release identity rather than silently changing the saved operation. The old publication intent is not reused or replayed.

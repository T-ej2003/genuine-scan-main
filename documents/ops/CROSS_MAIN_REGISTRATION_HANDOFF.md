# Current-main adoption of registered outputs

Use the existing staged-broker entry point with `operation: prepare-registration-adoption` and the recovered original registration chain. This phase performs only reads and an unlocked diagnostic Terraform plan. It cannot reserve authorization, write receipts, apply Terraform, register definitions, mutate services/tasks, or mutate broker/IAM state.

It verifies the original signed registration preparation, consumed reservation, durable intent and canonical TASK_REGISTERED receipt. Original source ancestry/tree and any recovery-tooling provenance are authenticated independently. Every original exact successor is described and compared with its approved definition. The current protected-main plan must show all twelve definitions as exact no-ops, with the same authenticated ARNs; the existing image-impact classifier must prove compatibility. No latest selection or revision arithmetic is used.

The output adds an explicit adoption record beside unchanged preparation/authorization/result. It binds original transaction hashes and definitions to the current source/tree and derived compatibility report. Feed that registration entry into prepare-policy and later staged-broker preparations. Independent authorization signs the complete current-main preparation, including adoption; the old consumed authorization is not authority for another mutation. Every downstream chain authentication rederives adoption against current clean main, a fresh task-definition plan and exact state/live readback.

Adoption does not claim registrations were produced by current main, complete deployment, or allow arbitrary old receipts. Changed images/templates/roles/environment, different successor identities, absent intent/reservation/receipt, incompatible sources and substituted provenance fail closed. Normal mutation execution still uses the unchanged exact-protected-main checkout requirement.

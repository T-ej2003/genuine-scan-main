## Bootstrap boundary

The repository does not currently have a production Terraform execution role, environment, or suitable monitor permissions boundary for this stack. A separately authorized, non-root infrastructure administrator must first install `bootstrap-monitor-boundary.json` as separately governed policy `MSCQRProductionEcrMonitorBoundary`, then establish two narrowly scoped OIDC roles using `bootstrap-plan-trust.json`, `bootstrap-apply-trust.json`, `bootstrap-read-policy.json` (on both roles), and `bootstrap-apply-policy.json` (apply role only). The exact role names are `mscqr-production-ecr-infrastructure-plan` and `mscqr-production-ecr-infrastructure-apply`. The plan role can read the protected inventory and acquire the exact S3 lock; it cannot write the state or production resources. The apply role can write only this state key and the named ECR/monitor-IAM/EventBridge/SNS/CloudWatch resources. Its `CreateRole` and `PutRolePolicy` grants require the exact monitor boundary; `TagRole` is scoped to that role only. It cannot change role trust, attach a managed policy, pass a role, remove the boundary, delete images or change ECS. The workflow reads back the boundary document before plan and apply. Bootstrap is a separate authorization boundary; no existing boundary was assumed.

The repository administrator must configure `production-ecr-infrastructure-plan` for protected `main` without static AWS secrets and `production-ecr-infrastructure-apply` for protected `main` with the required human reviewer and no admin bypass, exactly as `github-environment-contract.json` describes. Confirm both OIDC trusts against a live job token and simulate the exact role actions before approving an apply. The separate unattended `production-ecr-monitor` environment must also be configured before enabling monitoring. This PR creates none of these AWS or GitHub objects. Do not use root, the normal release-deployer, or a role with broader privileges as a fallback.

The monitor and infrastructure inventory gates check the exact AWS account, allowlisted assumed role, and a single nonempty session segment. The infrastructure SNS gate additionally excludes the monitor role. Focused tests reject wrong accounts, similar role names, empty sessions and unexpected ARN paths; live role assumption still requires post-bootstrap verification.

## Governed plan and apply

Dispatch `.github/workflows/production-ecr-protection-infrastructure.yml` only from protected main with its exact 40-character `source_sha`. All actions use verified upstream commit SHAs. The plan job verifies current main, assumes the plan role, authenticates the live boundary and protected-image inventory, initializes only this root, then verifies state ownership and the SNS policy's exact predecessor or managed successor before publishing a saved binary plan and JSON review view. It rejects modules, provisioners, drift, destroy/replace actions, unexpected managed addresses, and any lifecycle policy. The workflow holds the established `production-deploy` concurrency group.

Review the plan artifact, source SHA, current state ownership, and protected-environment request before approving `production-ecr-infrastructure-apply`. The apply job rechecks current main, exact plan SHA-256, live boundary, inventory and SNS policy under the apply role after approval, then applies **only** the saved plan. A stale or lost response requires native Terraform-state and AWS readbacks before any successor run; `GITHUB_RUN_ATTEMPT != 1` fails closed. The completion artifact records source, run, plan hash and observation time. It does not assert that monitoring is operational.

No plan can be generated in this PR before the approved OIDC roles and environments exist. Terraform `init -backend=false` and `validate` only prove source syntax and provider compatibility.

## Production rollout after an approved apply

1. Reauthenticate all active, worker, rollback, pending and open-journal digests. Check exact ECR digests and manifest children. Run current lifecycle previews for backend and web. Stop on incomplete inventory, missing digest, unavailable preview, or preview selecting a protected image. The workflow's inventory check does not authorize image retirement.
2. Review and apply the isolated saved plan. The new repository guards prohibit image deletion and future lifecycle-policy creation; they do not remove existing expiration policies.
3. Through a separately reviewed, non-root ECR repository-control action, remove the current backend and web lifecycle policies only after the protected inventory and previews are authenticated. Read back `LifecyclePolicyNotFoundException` for both. Keep worker without a lifecycle policy. Do not install a replacement count-based rule or delete images.
4. Read back all three repository guards, monitor IAM/OIDC trust, four alarms, two EventBridge targets, and the SNS policy with its original default statement. Prove the existing email subscription and one harmless alert delivery. Configure the unattended monitor environment, run the monitor once, and verify metrics and alarm recovery. Verify both image publishers can still push while deletion/lifecycle writes are denied.
5. Confirm ECS backend remains 2/2 healthy, frontend remains healthy, ALB has two healthy targets, and application/database readiness pass. Record Terraform state version, workflow plan/apply IDs, lifecycle-policy readbacks, exact digests, alert delivery and health in the operational completion receipt.

The current worker has no lifecycle policy. This root never creates one. Storage remains unbounded until a separate, reviewed retirement transaction exists. Do not claim Milestone 1 operationally complete from this source PR or a green Terraform apply alone.

## Hostile review and remaining boundary

The review reproduced four failure paths: an empty broad-root state could create unrelated resources; an existing resource absent from the new state could be overwritten; a saved plan could broaden monitor IAM or weaken repository guards; and a changed SNS default policy could be replaced on import. The isolated root, native ownership preflight, exact managed-resource/action/content plan guard, and pinned live SNS predecessor reject those paths. A lost apply response or partial state requires reconciliation; the workflow rejects reruns and incomplete state rather than retrying. GitHub serialization does not make external AWS writes atomic with Terraform. An external administrator could change the topic policy after the final read or remove a repository guard; final native readbacks, monitoring and the separate production authorization boundary remain necessary. Live OIDC assumption, targeted production plan, policy apply and alert delivery are unverified until bootstrap and rollout.

## Bootstrap boundary

The exact role names are `mscqr-production-ecr-infrastructure-plan` and `mscqr-production-ecr-infrastructure-apply`. The plan role can read the protected inventory and acquire the exact S3 lock; it cannot write the state or production resources. The apply role can write only this state key and the named ECR/monitor-IAM/EventBridge/SNS/CloudWatch resources. Its `CreateRole` and `PutRolePolicy` grants require the exact monitor boundary; `TagRole` is scoped to that role only. It cannot change role trust, attach a managed policy, pass a role, remove the boundary, delete images or change ECS. The workflow reads back the boundary document before plan and apply. Bootstrap remains a separate authorization boundary.

The configured `production-ecr-infrastructure-plan` environment permits protected `main` without static AWS secrets; `production-ecr-infrastructure-apply` permits protected `main` with a human reviewer and no admin bypass, as `github-environment-contract.json` describes. Both OIDC role assumptions succeeded in run `40342304424`. The separate unattended `production-ecr-monitor` environment is configured but its role assumption must be verified after the stack completes. Do not use root, the normal release-deployer, or a role with broader privileges as a fallback.

It rejects modules, provisioners, drift, destroy/replace actions, unexpected managed addresses, and any lifecycle policy. The workflow holds the established `production-deploy` concurrency group.

## Hostile review and remaining boundary

The review reproduced four failure paths: an empty broad-root state could create unrelated resources; an existing resource absent from the new state could be overwritten; a saved plan could broaden monitor IAM or weaken repository guards; and a changed SNS default policy could be replaced on import. The isolated root, native ownership preflight, exact managed-resource/action/content plan guard, and pinned live SNS predecessor reject those paths. A lost apply response requires native reconciliation; the workflow rejects reruns and any partial state other than the authenticated run `40342304424` snapshot. GitHub serialization does not make external AWS writes atomic with Terraform. An external administrator could change the topic policy after the final read or remove a repository guard; final native readbacks, monitoring and the separate production authorization boundary remain necessary. The next governed plan, ECR policy acceptance and alert delivery remain unverified.

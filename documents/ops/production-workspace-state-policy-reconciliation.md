# WorkspaceState policy reconciliation

The target-specific reconciler changes only `MSCQRProductionGreenStageBWorkspaceState`. A normal preparation authorizes the exact reviewed deletion candidate and declared successor. The executor checks authorization freshness immediately before each new IAM write.

If deletion's final bounded read fails transiently, the executor writes `deletion-prewrite-failed.json` only after the DeletePolicyVersion call was skipped. A fresh preparation can be created from the unchanged live pre-state with `--mode prepare-continuation --continuation-kind PROVED_NO_DELETE_WRITE`; the resulting preparation binds the original preparation and the exact reservation, deletion-attempt, and no-write proof digests. Its fresh independent authorization permits one delete retry only. After that delete is observed and recorded, the executor stops with `DELETION_COMPLETED_AWAITING_FRESH_CREATE_AUTHORIZATION`.

For the next step, create another continuation with `--continuation-kind PROVED_NO_CREATE_WRITE`. This requires the exact deletion-complete record, no creation-attempt or terminal record at preparation time, and the exact live four-version post-deletion state. Its fresh independent authorization permits one CreatePolicyVersion call only.

An existing retry-attempt or creation-attempt is never treated as proof that the corresponding write was skipped. A retry-attempt with the exact five-version pre-state remains uncertain and cannot be replayed; with the exact four-version post-delete state, the approved candidate is absent and every retained version/document and the unchanged default are reauthenticated before deletion-complete is recorded read-only. Any other inventory fails closed. A creation-attempt with the exact successor is likewise reconciled without another create; an unchanged capacity state remains uncertain. An expired authorization may authenticate records and terminalize an already-observed exact successor, but cannot authorize another IAM write.

The continuation command reads the canonical S3 journal and live IAM state. It does not write AWS resources. Use `--mode prepare-continuation --source-sha <protected-main-sha> --base-preparation <private-preparation.json> --base-preparation-file-sha256 <sha256> --continuation-kind PROVED_NO_DELETE_WRITE` or `--continuation-kind PROVED_NO_CREATE_WRITE`, with `--preparation-out <new-private-preparation.json> --admin-profile <governed-profile>`. Then use the existing authorization workflow for that exact new preparation and the normal `--mode execute` path. Keep each preparation and authorization private and pass its exact file digest through the existing protected workflow.

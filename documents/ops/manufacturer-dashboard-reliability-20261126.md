## Repair and acceptance

- Use the existing manufacturer branch of the authoritative dashboard snapshot for the allocation KPI, progress and distribution on REST, manual refresh and SSE. Count one identity per current QR row whose batch belongs to the authenticated manufacturer in an active linked scope. QR status is a single value. Assigned groups `ALLOCATED` and `ACTIVATED`, and Printed uses `PRINTED`. Scanned groups `SCANNED` and `REDEEMED`. Other allocated includes all remaining owned states, including blocked or dormant identities. Revoking the matching relationship removes the QR from that manufacturer's scope. Scan and print-attempt rows cannot increase the identity count.
- The observed 73 and 6 are disjoint under the source grouping, and sum to 79 for those two buckets. The reported chart also showed 79. The complete production allocation total still requires an authoritative count in that workspace, including any other owned lifecycle states.
- Keep the manufacturer dashboard off the brand-level `/api/qr/stats` route and reject manufacturer requests to that HTTP route. The existing daily scan count runs on the dashboard request for supported manufacturer admins. This API change requires coordinating the frontend and backend application release so an older manufacturer dashboard does not continue calling the brand inventory route.
- Use the existing `/api/audit/logs` selected-workspace boundary for the personal feed. A brand switch uses that brand's own authorized history. The feed uses the server's inclusive UTC 48-hour window, existing five-row limit and descending timestamp/ID order. It excludes self-generated dashboard and audit read records. The existing actor/tenant filters, redaction and RLS apply. A live event can trigger a fresh authorized read without sending personal audit payloads over SSE. Cached degraded reads and failed reads have explicit UI states.
- Start manufacturer SSE and the activity read after the initial stats request settles. This removes the brand inventory call and keeps the initial manufacturer dashboard stats request from racing its own SSE authentication. Licensee and platform views keep their current stats and activity behavior.
- The PostgreSQL application-path test is a source-contract input. The generated certification hash and package guard metadata were refreshed with the repository generator. Migrations, policy predicates, grants, routine definitions and FORCE RLS semantics are unchanged.

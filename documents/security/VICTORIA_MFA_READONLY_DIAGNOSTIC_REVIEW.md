# Victoria MFA diagnostic: disabled review artifact

**NOT AUTHORIZED FOR PRODUCTION DEPLOYMENT.** The standalone SQL is not registered with the package generator or any workflow. It creates a dedicated NOLOGIN, NOSUPERUSER, NOBYPASSRLS owner, column-scoped SELECT privileges and target-scoped SELECT policies. It requires existing FORCE RLS, a read-only transaction, a fixed email and a locked search path. It grants no operator EXECUTE permission and fails if unexpected default function grants exist. Negative account and factor results remain unknown; a hidden row is not proof of absence.

The reviewed operator must not get direct table privileges. A future exact EXECUTE grant, role identity and policies need independent review against the live PostgreSQL catalogue. The function owner needs access to the legacy backup-code hash array only to compute whether any exist; no hashes or secrets are returned. Installation and eventual cleanup are separate privileged catalog operations, not performed by this change.

The result validator accepts only the fixed projection. The runner always refuses execution: there is no authenticated operator/approval provider or durable audit adapter in this artifact. A caller-supplied identity is not proof of authorization. The existing C04 audit helper writes audit and outbox rows, which PostgreSQL rejects inside a read-only transaction. A future reviewed integration must durably persist STARTED before the read-only query and COMPLETED or FAILED after it, authenticate both operator and authorization, and release no result until audit durability is verified. Failed transactions and denied invocations need an independent durable audit source; no immutable-retention claim is made here.

Execution map: the existing MFA-gated ECS Exec verifier authenticates a specific AWS role but is bound to a different rotation proof, not this diagnostic. The C04 helper accepts database context values supplied by its caller and relies on a database login identity; neither is an independently authenticated operator approval for this operation. Its audit helper inserts into AuditLog and SecurityEventOutbox in the caller's transaction. Neither path supplies the missing target-bound operator authorization, audit commit receipts or a private fixed-command invocation. The diagnostic retains no EXECUTE grant until a reviewed integration proves all of them. The database function itself never writes audit records.

Production prerequisites include exact source and database binding, proof of FORCE RLS and existing policies, non-login ownership and role memberships, reviewed minimal permissions, a private execution channel, authenticated approval, durable auditing, denial and rollback tests, and separate installation approval. No MFA reset is included.

Tests: `node backend/tests/rls-wave-c/c04/victoriaDiagnosticPostgres.test.js` uses a disposable network-isolated PostgreSQL 18 container; `node --test scripts/tests/victoria-diagnostic-result.test.mjs` tests the disabled runner and result validation. This artifact must not be executed against production without separate review and authorization.

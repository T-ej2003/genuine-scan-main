# Production security-rebaseline image signer

The isolated Terraform root `infra/aws/terraform/production-security-rebaseline-signer`
creates one GitHub OIDC role and one purpose-specific RSA-3072 KMS key for
signing read-only security-rebaseline image authorizations. The role can call
only `kms:Sign` on that exact key, with the specified digest message type and
RSA-PSS-SHA256 algorithm. It cannot publish images, read databases, register
ECS tasks, deploy, administer IAM, or administer the key. The existing
root-attestation key and policy are unchanged.

The trust policy requires the exact default repository/environment subject,
`sts.amazonaws.com` audience, immutable repository and owner IDs, `main` ref,
and the pinned reusable signing-workflow `job_workflow_ref`. AWS maps these
GitHub claims to IAM condition keys. The signing job also verifies the exact
calling preparation workflow, source SHA, repository identity, and first-run
identity before assuming the role. GitHub's protected signing environment must
allow protected branches only, require an independent reviewer, prevent
self-review, contain only the signer-role ARN variable, and have no secrets.
The workflow reads back these conditions before requesting AWS credentials.

After this PR is reviewed and merged, a separately authorized MFA-backed,
non-root operator must plan and apply this root through the canonical encrypted
S3 Terraform backend and its dedicated state key. No AWS/IAM/KMS resource is
changed by this source package or its tests.

```sh
terraform -chdir=infra/aws/terraform/production-security-rebaseline-signer init \
  -upgrade=false -input=false -lockfile=readonly \
  -backend-config='bucket=mscqr-production-terraform-state-368992683803-eu-west-2' \
  -backend-config='key=mscqr/production/security-rebaseline/signer/terraform.tfstate' \
  -backend-config='region=eu-west-2' \
  -backend-config='encrypt=true' \
  -backend-config='use_lockfile=true'
terraform -chdir=infra/aws/terraform/production-security-rebaseline-signer plan -out=signer.tfplan
terraform -chdir=infra/aws/terraform/production-security-rebaseline-signer apply signer.tfplan
```

Only after verified apply should `signer_role_arn` be set as the variable on
the exact protected GitHub environment. No repository-level variable, AWS
credential secret, or production environment mutation is part of this PR.

After that separately authorized apply, Terraform `plan -detailed-exitcode` is
the drift gate. Then run
`node scripts/aws/verify-production-security-rebaseline-signer.mjs --aws-profile
<approved-readback-profile>`. This verifier makes read-only IAM/KMS calls and
fails closed on trust, inline/attached permissions, key-policy, key, alias, or
grant drift. It reports only bounded policy digests and identities. The daily
preparation workflow does not need this privileged readback profile; its OIDC
session receives no IAM read or KMS administration permissions.

The preparation workflow's authorization is valid for 24 hours; its GitHub
artifacts are retained for 90 days for audit/regeneration coordination only.
Expired evidence must be regenerated by a new first-attempt run from the exact
source. Reruns and older artifacts are rejected.

The verifier requires a native cutover result, exact inventory completion row, ECS registration payload and completion journal, live task definition, Stage B Terraform state and IAM policy, secret version metadata, MFA AssumeRole and ECS RegisterTaskDefinition CloudTrail events, and a fresh one-use checker signature over the agreed native proof. The checker and hosted role each perform their own AWS census. The source-managed IAM additions have not been applied or read back, and the CloudTrail event shape and IAM boundary have only synthetic-test coverage. Phase 3 must independently prove those live read-only capabilities before signing or deployment. A missing historical registration payload remains an explicit fail-closed case; it must not be fabricated.
2. **Post-mutation Release Gate recovery is implemented locally and still needs exact-head CI and review.** Normal Gate journals the bound backend preflight, claims the ECS transition, verifies the exact task digest and service settings, and reconstructs metadata after an authenticated lost response. The Stage B candidate may already be the overlap service revision: recovery distinguishes that exact no-update case from a foreign revision. The frontend marks registration with a source-bound operation tag, scans and verifies that revision, and never registers again after an ambiguous dispatch. ECS completion receipts capture the native service ARN and deployment ID; a subsequent deployment ID change fails closed. The frontend journals the service update and stable health readback. A failed normal child resumes under its original GitHub run ID after the parent verifies native journals and live ECS state. The existing RLS broker checks per-mode native receipts and one-use claims before replay. DynamoDB component-state commit has a write-ahead claim and exact state readback; smoke has an attempt-bound receipt and repeats only read-only HTTP checks. A changed source, resource, image, component provenance, or ambiguous AWS outcome stops. The normal backend task definition was registered by Stage B, so Gate does not register another backend revision. Failed overlap children use the existing zero-update native reconciliation only when the exact target and running digest are stable. GitHub retains approval history per run; a rerun now accepts repeated approval by the same independent reviewer while the current protected job must pass its own approval step. Conflicting reviewers fail closed. This behavior has synthetic tests but no non-production protected-environment rehearsal.
3. **Artifact-signing bootstrap is deliberately fail closed at an unrecoverable partial key state.** `production-artifact-signing-secrets-adapter.mjs` now supplies a deterministic 64-character client request token, verifies the native `VersionId`, and reads back that exact version and value. `production-artifact-signing-domain.mjs` reuses a persisted private key after a lost response, while a partial domain with no recoverable private key stops instead of generating another key. The first in-memory key generation still has no separately governed durable escrow before its first write. A lost response with no authoritative version readback remains `OUTCOME_UNKNOWN`; separate authorized reconciliation is required. This is a deployment recovery limit, not permission to regenerate a key from an ambiguous state.

## Corrected finding on this head

The previous Codex review found that polling ended after 30 minutes even when a native Sign was dispatched. The parent now observes the exact authorization round for a bounded five-hour interval and stops at request expiry when no Sign for that round exists. A Sign from a previous round cannot extend a newer request. A later P1 review found that root Sign just before request expiry could strand adoption. A new protected Release Train authorization round can now resume with the original root result, but only after its exact original timely dispatch, request, signer, canonical payload, native KMS signature, and key ARN verify. Each new checker Sign uses the new round and its own expiry. An unknown Sign result blocks renewal. Root age remains 900 seconds with a 120-second pre-verifier reserve. Focused tests cover late root Sign, expired adoption authority, renewed checker signing, duplicate root refusal, and unknown outcome. AWS KMS documents Sign and Verify `KeyId` responses as key ARNs even when an alias is supplied; root journal verification now compares those native key ARNs while requiring the reviewed alias as input. No live Sign was run.

Codex review of `2333b4a4` found two more P1 recovery defects. The native result classifier read identity fields from the wrong level of the `{dispatch,response}` journal result, and a new request could collide with an old unused phase timestamp. The classifier now compares the nested dispatch and completion to the immutable claim. Timestamp reservation skips records owned by earlier request rounds. Regression tests use the real journal shape and cross-round timestamp recovery.

The subsequent P1 review found that the hosted waiter could poll an expired request indefinitely when three Sign results were complete but no operator claim existed. The terminal could not claim that expired request. Both paths now use one expiry decision contract. The operator claim binds the exact request and native input and must be initiated inside the authorization window. The hosted waiter reauthorizes immediately when no claim exists, fails closed on a mismatched or late claim, and preserves each completed signature. A Sign dispatch with no result remains `OUTCOME_UNKNOWN`. Completion authentication also requires the timely operator claim. Codex found that stopping after a claim readback crosses expiry strands a claimed but unstarted native operation; the terminal now continues the exact claimed operation. Focused tests cover the original deadlock, matching and forged claims, claim readback crossing expiry, and unknown Sign outcomes. A claim response lost across expiry remains an ambiguous operator state requiring reconciliation; it is never treated as a fresh attempt.

The next review found that Release Train selected the prerequisite lifecycle for bridge mode without setting `RELEASE_PREREQUISITES_ONLY`; the coordinator rejected the run before the bridge. The workflow now sets that flag for either prerequisite mode or trusted-terminal mode, with a parsed-YAML contract test. The operator-claim review also found that a client timestamp sampled before expiry cannot prove when S3 committed the atomic claim. The shared expiry decision now requires the native S3 `LastModified`; a claim committed after expiry fails closed, while a timely commit survives delayed readback. A late or ambiguous claim still requires separately authenticated reconciliation.

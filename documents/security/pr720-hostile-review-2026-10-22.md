# PR #720 hostile security review — 22 October 2026

This review covers the trusted-terminal bridge at commit `52265068f574d23dae36c37be7c0bf4c840a9ff1`. It uses source inspection and non-production tests; no production cutover or KMS Sign was run. **The PR is not ready to merge or deploy.**

## Blocking findings

1. **Native Stage B completion is not independently authenticated.** `run-hosted-production-release-bridge.mjs:44` intentionally requires a verifier that its CLI does not supply. `run-production-release-terminal-bridge.mjs:208-221` persists readiness and the three earlier signature artifacts, but no separately authorized checker signature over the final verifier-owned native outcomes. `production-cutover-control-plane.mjs:416-440` records readiness stage references and returns richer in-process results; a stage reference or terminal completion flag is not an authoritative AWS result. The interactive verifier session is process scoped. The approved contract change must add a fresh, one-use post-cutover checker authorization and signed result, plus hosted KMS verification and authoritative AWS readbacks for MFA issuance, inventory, Terraform, Secrets Manager, task registration, and prepared overlap. Until then, the line 44 guard must remain.
2. **Partial Release Gate runs have no safe continuation.** `run-hosted-production-release-bridge.mjs:145-212` pins one overlap and one normal child run. It can reuse a failed normal run only when the deployment job, receipts, smoke and live state all prove completion. If that run stops after any earlier mutation, the same child is read again and fails; there is no per-transition continuation. New dispatch based on GitHub failure would risk repeating RLS, ECS, frontend or component-state writes. Each transition needs a durable claim, exact native result, readback classifier, and Gate entry point that skips authenticated completed steps.
3. **Secrets Manager writes lack a durable native version result and reproducible input.** `production-artifact-signing-secrets-adapter.mjs` discards the `PutSecretValue` response and returns only a secret reference. `production-artifact-signing-domain.mjs` generates an Ed25519 private key in memory when all four secrets are empty, then publishes it across separate writes. After a process crash or lost response, the original key input may be irretrievable, so a new run must not generate and publish a different key as if it were a retry. A safe design needs an approved protected durable input escrow or separately authorized manual reconciliation, a stable Secrets Manager client request token, native version ID capture, and read-only exact version comparison. The current contract supplies none of these together. An absent CLI response remains `OUTCOME_UNKNOWN`.

## Corrected finding on this head

The previous Codex review found that polling ended after 30 minutes even when a native Sign was dispatched. The parent now observes the exact authorization round for a bounded five-hour interval and stops at request expiry when no Sign for that round exists. A Sign from a previous round cannot extend a newer request. A later P1 review found that root Sign just before request expiry could strand adoption. A new protected Release Train authorization round can now resume with the original root result, but only after its exact original timely dispatch, request, signer, canonical payload, native KMS signature, and key ARN verify. Each new checker Sign uses the new round and its own expiry. An unknown Sign result blocks renewal. Root age remains 900 seconds with a 120-second pre-verifier reserve. Focused tests cover late root Sign, expired adoption authority, renewed checker signing, duplicate root refusal, and unknown outcome. AWS KMS documents Sign and Verify `KeyId` responses as key ARNs even when an alias is supplied; root journal verification now compares those native key ARNs while requiring the reviewed alias as input. No live Sign was run.

Codex review of `2333b4a4` found two more P1 recovery defects. The native result classifier read identity fields from the wrong level of the `{dispatch,response}` journal result, and a new request could collide with an old unused phase timestamp. The classifier now compares the nested dispatch and completion to the immutable claim. Timestamp reservation skips records owned by earlier request rounds. Regression tests use the real journal shape and cross-round timestamp recovery.

The subsequent P1 review found that the hosted waiter could poll an expired request indefinitely when three Sign results were complete but no operator claim existed. The terminal could not claim that expired request. Both paths now use one expiry decision contract. The operator claim binds the exact request and native input and must have a claim time inside the authorization window; terminal claim readback must finish before expiry. The hosted waiter reauthorizes immediately when no claim exists, fails closed on a mismatched or late claim, and preserves each completed signature. A Sign dispatch with no result remains `OUTCOME_UNKNOWN`. Completion authentication also requires the timely operator claim. Focused tests cover the exact deadlock, matching and forged claims, expiry at claim readback, and unknown Sign outcomes. A claim response lost across expiry remains an ambiguous operator state requiring reconciliation; it is never treated as a fresh attempt.
